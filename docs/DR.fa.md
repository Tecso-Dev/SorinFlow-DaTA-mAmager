# بازیابی فاجعه (Disaster Recovery)

اگر سرور از بین برود، این راهنما می‌گوید چطور روی یک سرور تازه همهٔ اطلاعات را — بدون گرفتن دوبارهٔ هیچ کلید API‌ای — بالا بیاورید.

---

## چه چیزی هر شب به تلگرام می‌رود

هر شب ساعت ۴ صبح (به‌وقت تهران)، و هر وقت از پنل دکمهٔ «همین حالا» زده شود، `scripts/dr_backup.sh` روی خودِ سرور (نه داخل پاد) یک بستهٔ رمزشده می‌سازد و به همان چت تلگرامی که بکاپ شبانه می‌رود، می‌فرستد:

- **پایگاه داده کامل** (`pg_dump` فرمت فشرده) + `pg_dumpall --globals-only` (نقش‌ها و رمزهای Postgres) + شمار ردیف‌های هر جدول
- **کل Secret کوبرنتیز** — یعنی `SECRET_KEY`، رمز پایگاه داده، و هر کلید API که تا آن لحظه ثبت شده (LLM، پیامک، ایمیل، تلگرام)
- از حجم داده (`data-pvc`): **آواتارها، جلسات دیوار (کوکی‌ها) و پروفایل‌های مرورگر** (دستگاهی که دیوار آن را می‌شناسد)
- گواهی SSL که Traefik دارد (`acme.json`) — تا سایت همان لحظه که DNS منتقل شود، HTTPS جواب بدهد

## چه چیزی در آن **نیست** و چرا

- **عکس آگهی‌ها** — این‌ها را می‌شود دوباره از دیوار اسکرپ کرد؛ حجمشان زیاد است و نگه‌داشتنشان در بکاپ فقط اندازهٔ بسته را بی‌جهت بزرگ می‌کند.
- **کش کروم** (Cache، Code Cache، GPUCache، ShaderCache و مشابه، داخل پروفایل هر حساب) — این‌ها فقط کش مرورگرند؛ نبودشان یعنی اولین بازدید بعد از بازیابی کمی کندتر است، همین.
- **`downloads/`**: فقط APK فورواردر است که سرور هر چند ساعت خودش دوباره می‌گیرد.
- **`backups/`**: ۱۴ نسخهٔ JSON شبانه از همان پایگاه داده که `pg_dump` بالا کاملش را دارد. با آن‌ها بسته چند برابر می‌شد.

بسته رمزنگاری‌شده است (`DR_BACKUP_PASSPHRASE`) و به تکه‌های ۴۵ مگابایتی تقسیم می‌شود تا زیر سقف ۵۰ مگابایتی تلگرام بماند؛ یک فایل «فهرست» (manifest) همراهش می‌آید که شمارهٔ sha256 هر تکه را دارد.

## رمز عبور از کجا می‌آید

`DR_BACKUP_PASSPHRASE` در GitHub Secrets تنظیم می‌شود، مثل بقیهٔ کلیدها روی هر دیپلوی در Secret کوبرنتیز (`sorinflow-secrets`) هم‌گام می‌شود. سرور خودش، در لحظهٔ ساخت بکاپ، آن را از همان Secret می‌خواند — یعنی یک نسخهٔ دوم از رمز روی دیسک سرور نگه‌داری نمی‌شود.

---

## بازیابی، گام‌به‌گام

۱. تکه‌های همان بکاپ (و فایل manifest، با نام `manifest.json` یا `sorinflow-dr-<تاریخ>.manifest.json`) را از تلگرام دانلود کنید و همه را در یک پوشه بگذارید.

۲. رمز `DR_BACKUP_PASSPHRASE` را کنار دست داشته باشید (همانی که در GitHub Secrets است)، سپس:

```bash
bash scripts/dr_restore.sh <پوشهٔ تکه‌ها>
```

این اسکریپت به اینترنت نیاز ندارد. کاری که می‌کند:
- شمارهٔ sha256 هر تکه را با manifest چک می‌کند — اگر تکه‌ای گم باشد یا دستکاری شده باشد، نام همان تکه را می‌گوید و **چیزی را بازیابی نمی‌کند**.
- رمز را می‌پرسد (یا از `DR_BACKUP_PASSPHRASE`/`DR_PASSPHRASE_FILE` می‌خواند)، بسته را رمزگشایی و باز می‌کند.
- در پایان، دستور دقیق مرحلهٔ بعد را چاپ می‌کند.

۳. همان دستوری که چاپ شد را روی سرور **تازه** اجرا کنید — چیزی شبیه:

```bash
bash scripts/new_server.sh <پوشهٔ باز‌شده> [توکن ثبت‌نام runner گیت‌هاب]
```

`scripts/new_server.sh` از صفر سرور را بالا می‌آورد: k3s، Traefik با همان گواهی قدیمی، Secret با همان کلیدها، پایگاه داده از همان dump، حجم داده از همان آرشیو — و در پایان همین تایمر بکاپ فاجعه را هم خودش دوباره نصب می‌کند.

۴. اگر `dr_restore.sh` گفت کلیدی از Secret چندخطی است (مثل کلید PEM یا JSON حساب سرویس)، آن کلید در فایل env نیست، چون `new_server.sh` هر خط را یک کلید می‌خواند. بعد از `new_server.sh` همان دستوری را که چاپ کرد بزنید تا همهٔ کلیدها دقیقاً برگردند:

```bash
kubectl apply -f <پوشهٔ باز‌شده>/k8s/sorinflow-secrets.json
```

---

## کاری که باید دستی انجام شود

- **GitHub Secret:** در تنظیمات ریپو، `DR_BACKUP_PASSPHRASE` را یک‌بار بسازید (یک رشتهٔ تصادفی بلند) و جایی امن (نه در این ریپو) نگه دارید — همان رمز، هم برای بازیابی لازم است.
- بعد از ساخت آن Secret، یک دیپلوی معمولی (push به `main`) کافی است تا هم به Secret کوبرنتیز برسد و هم تایمر روی سرور نصب/به‌روز شود.
- **اولین اجرا:** بعد از آن دیپلوی، یا صبر کنید تا ساعت ۴ برسد، یا از پنل دکمهٔ «همین حالا» را بزنید، و بعد چک کنید که پیام بکاپ در تلگرام رسیده باشد.
- توکن ثبت‌نام runner گیت‌هاب (برای مرحلهٔ آخر `new_server.sh`) را از `github.com/Tecso-Dev/SorinFlow-DaTA-mAmager` → Settings → Actions → Runners در لحظهٔ بازیابی می‌گیرید؛ این را از قبل نمی‌شود ذخیره کرد چون کوتاه‌مدت است.
