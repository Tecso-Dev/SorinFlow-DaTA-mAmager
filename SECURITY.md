# Security Policy — سیاست امنیتی

## Reporting a vulnerability

**Please do not open a public issue for a security problem.** An issue is
visible to everyone the moment it is filed, including whoever would exploit it.

Report it privately, whichever is easier:

- **GitHub** — [open a private advisory](https://github.com/Tecso-Dev/SorinFlow-DaTA-mAmager/security/advisories/new)
  (Security → Advisories → *Report a vulnerability*)
- **Email** — sobhan.gjhav.azimzadeh@gmail.com

Please include what you can: what the flaw is, how to reproduce it, and what an
attacker gets out of it. A rough report sent early is worth more than a polished
one sent late.

You can expect an acknowledgement within a few days. This is a small team
running one production system, not a vendor with a security desk — but reports
are taken seriously and fixed properly, not papered over.

## Scope

This project runs a real estate CRM and a Divar.ir scraper. Findings that matter
most here:

- Anything reaching data across a tenant or role boundary — the roles are
  `root`, `super_admin`, `admin` and `visitor`
- Authentication and session handling: JWT issuance and validation, the TOTP
  second factor, the SMS verification codes for portal sign-up
- Stored XSS in the dashboard or the customer portal, which is amplified by the
  token living in `localStorage`
- Exposure of scraped personal data: phone numbers, Divar session cookies, and
  the nightly backup
- Anything unauthenticated: `/api/public/auth/*` and the portal pages

Out of scope: findings that require an already-compromised server, denial of
service by raw volume, and reports generated by a scanner with no demonstrated
impact.

## Handling secrets

If you find a credential committed to this repository, please report it
privately rather than filing an issue — an issue advertises it. See
[SECRETS.md](SECRETS.md) for where secrets are supposed to live and how they are
rotated.

The history was rewritten in August 2026 to purge previously committed secrets.
Anything exposed before then is treated as compromised and rotated; purging the
history does not un-publish a value that was already public.

## Supported versions

Only the current `main` branch, which is what runs in production. There are no
maintained release branches.
